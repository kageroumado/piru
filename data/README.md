# `data/` — Substance data, source of truth

Everything in this directory is version-controlled, GitHub-diffable, and
human-readable. It is the **canonical source of truth** for the substance
knowledge Piru ships with.

Piru's runtime database (`Piru/Data/piru-substances.sqlite`) is a *build
artifact* generated from these files by [`pipeline/`](../pipeline/). To
inspect what the app knows, **start at [`snapshots/`](snapshots/)** — it
mirrors the SQLite content in JSON and CSV form.

To contribute a correction or addition, you almost always want to edit a
file under [`curated/`](curated/) (a hand-maintained overlay that wins
against external sources) — see "Contributing a substance change" below.

## Layout

```
data/
├── sources/        Raw per-source dumps as ingested from external providers
├── curated/        Hand-maintained overrides (highest priority, wins on conflict)
├── intermediate/   SubstanceCollector merge outputs — generated, not hand-edited
├── enrichment/     LLM-assisted deep-pharma research (peer-review-primary source)
└── snapshots/      ★ Human-readable mirror of the shipped SQLite ★
```

### `sources/` — raw per-source dumps

One JSON or CSV file per upstream provider, in roughly the shape that
provider gives us. These are inputs to the pipeline; the app never reads
them directly.

| File | Source | Provenance slug | What it contains |
|------|--------|-----------------|------------------|
| `psychonautwiki.json` | [PsychonautWiki](https://psychonautwiki.org) GraphQL API | `psychonautwiki` | Per-substance dose ranges, duration phases, tolerance info. Refreshed by `pipeline/fetch/psychonautwiki.py`. |
| `drug-community.json` | drug.community dump | `drug.community` | User-reported dose ranges across many compounds. |
| `drug-community-names.json` | drug.community | — | Name-only catalog used for alias detection. |
| `brushers/*.csv` | TripSit / MedTAP / NPS DataHub / Pyrls | various | Tabular CSVs brushed from external datasets by `pipeline/fetch/brushers/`. |

### `curated/` — hand-maintained overrides

`overlay.json` is the [`piru-curated`](../docs/sqlite-schema.md) source.
It has the highest default priority and wins against any external source
on conflicts. Use it to:

- Correct dose ranges where the upstream source is wrong or unsafe
- Add aliases / common names that crawlers missed
- Add half-life or duration data for substances external sources lack
- Override category assignments

Schema mirrors the `Substance` Codable struct in
`Piru/Models/Substance.swift`. The Swift `SubstanceCollector` reads this
file in `Curation/CuratedOverlay.swift` and bakes overrides into
`intermediate/sourced-substances.json` before the SQLite build.

### `intermediate/` — SubstanceCollector outputs

| File | Producer | Consumer |
|------|----------|----------|
| `sourced-substances.json` | `Tools/SubstanceCollector` | `pipeline/build/sqlite.py` |
| `substances-bundled.json` | `Tools/SubstanceCollector` (merged view) | `pipeline/build/snapshots.py`, fallback for sqlite.py |

These are regenerated on every collector run — don't hand-edit them, edit
[`curated/overlay.json`](curated/) instead and rerun the collector.

### `enrichment/` — LLM-assisted research

Deep-pharma research generated by an agent swarm. Carries the
`peer-review-primary` provenance slug and supplies things external sources
rarely have: receptor affinities (Ki values), metabolic pathways, primary
literature citations, class-context summaries.

```
enrichment/
├── groups/          Group assignments (one file per mechanism class) — tracked
├── raw/             Per-group LLM outputs (one file per group) — tracked
├── merged.json      Flat merge of all per-substance enrichment records — gitignored
├── class-context.json   Class-level summaries (e.g. "all NMDA antagonists") — gitignored
└── coverage.csv     One row per substance, columns flag which fields got filled — gitignored
```

Inputs to the SQLite build are `raw/*.json` (sqlite.py iterates them
directly). The three gitignored files are pure derivatives of `raw/`
produced by `pipeline/enrichment/merge.py` for inspection only — run
`python3 pipeline/enrichment/merge.py` to regenerate them locally.

### `snapshots/` — what the app actually ships

**This is where you look if you want to see what Piru knows.** Generated
from the SQLite by `pipeline/build/snapshots.py`. See
[`snapshots/README.md`](snapshots/README.md) for details.

## Contributing a substance change

The flow for fixing or extending substance data:

1. **Find what's wrong** by browsing [`snapshots/substances.csv`](snapshots/substances.csv)
   or [`snapshots/by-category/`](snapshots/by-category/). The CSV is the easiest
   to grep / spreadsheet-filter.
2. **Edit [`curated/overlay.json`](curated/overlay.json)** to add or correct the
   fact. The curated source wins against external sources at runtime, so this
   is enough to ship a fix without touching upstream providers.
3. **Regenerate** by running:
   ```bash
   cd Tools/SubstanceCollector && swift run SubstanceCollector
   python3 pipeline/build/sqlite.py
   python3 pipeline/build/snapshots.py
   ```
4. **Commit** the changes to `curated/overlay.json` + the regenerated
   `intermediate/`, `snapshots/`, and `Piru/Data/piru-substances.sqlite`.
5. **Open a PR**. The diff in `snapshots/substances.csv` will show exactly
   what your change does to user-visible values.

For schema details, see [`docs/sqlite-schema.md`](../docs/sqlite-schema.md).
For known data gaps, see [`docs/known-limitations.md`](../docs/known-limitations.md).
