# `data/snapshots/` — what Piru ships

This directory is the **human-readable mirror** of the SQLite database the
iOS app actually reads (`Piru/Data/piru-substances.sqlite`). If you want
to see what data Piru contains without installing SQLite tooling, look
here.

Both `substances.json` and `substances.csv` are generated by
`pipeline/build/snapshots.py` from the same SubstanceCollector outputs
that feed the SQLite build, so they're always in sync with what the app
ships.

## Files

| File | Best for | Contents |
|------|----------|----------|
| **`substances.csv`** | grep, spreadsheets, quick diffs | One row per substance with semicolon-delimited multi-value cells. Easiest to scan in GitHub's CSV viewer. |
| **`substances.json`** | full fidelity, programmatic use | Same data as `substances.csv` but with the original nested shape (per-route dose ranges, alias arrays, etc.) preserved. |
| **`gaps.csv`** | finding things to fix | Subset of `substances.csv` containing only substances with missing data (no dose range, no half-life, no category, etc.). Good PR target list. |
| **`by-category/`** | browsing by drug class | One `.txt` file per category (Stimulant, Psychedelic, Benzodiazepine, …) plus `_INDEX.md`. Shows canonical name + winning source + aliases for every substance in that category. Generated by `pipeline/audit/dump_substance_library.py`. |

## Relationship to the shipped SQLite

```
data/curated/overlay.json  ──┐
data/sources/*.json        ──┼──► pipeline/build/sqlite.py    ──► Piru/Data/piru-substances.sqlite  (app reads this)
data/intermediate/*.json   ──┤                                       │
data/enrichment/raw/*.json ──┘                                       │
                                                                     ▼
                              pipeline/build/snapshots.py  ──► data/snapshots/  (you read this)
```

The SQLite and the snapshots are built from the same inputs in the same
pipeline run. Don't expect them to ever drift — if they do, that's a
pipeline bug.

## Why we don't ship JSON instead

The iOS app used to load JSON at startup. We moved to a bundled SQLite in
the `feat/multi-source-substance-db` work to support proper per-source
attribution (every fact knows which source supplied it) and per-field
priority resolution at query time. JSON has no good answer for either.
The snapshots give you the inspectability of JSON without the runtime
cost.
